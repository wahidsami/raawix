# TRACK B — REPORT LOCALIZATION VERIFICATION

## Root Cause
The generated PDF and Excel reports lacked complete Arabic localization because WCAG rule names and issue descriptions were translated exclusively inside the `report-ui` frontend application (`apps/report-ui/src/utils/wcag-rules.ts`). The backend report generators (`apps/scanner`) read findings directly from the database, receiving only the hardcoded English messages generated by the rule engine (`packages/rules/src/wcag-rules.ts`), and had no access to Arabic translations.

## Architecture Implemented
We resolved the split-brain architecture by promoting the translation dictionary into a centralized, framework-independent metadata source within the shared `packages/rules` library. 
1. `wcagRulesMap` and its associated helpers (`getWCAGRuleTitle`, `getWCAGRuleDescription`, `getRuleMeta`, `formatWCAGId`) were moved to `packages/rules/src/wcag-metadata.ts` and exported from the package.
2. The UI (`apps/report-ui`) was updated to consume this shared package instead of maintaining a local copy.
3. The report generators (`pdf-export.ts` and `excel-report-generator.ts`) were updated to dynamically look up localized titles and descriptions based on the requested `locale` at generation time, injecting them alongside the raw technical message stored in the database.

## Files Changed
- **`apps/report-ui/src/utils/wcag-rules.ts`**: DELETED (relocated to `packages/rules`).
- **`packages/rules/src/wcag-metadata.ts`**: NEW (centralized metadata source).

- **`apps/scanner/src/api/pdf-export.ts`**: MODIFIED (resolved localized rules, prioritized title over ID).

## Verification Status

### PDF Verification
- **English**: Generates successfully. Displays the English human-readable rule title as the primary identifier (e.g., "Contrast Minimum"), with the WCAG ID ("WCAG 1.4.3") displayed secondarily below it. Displays the English description alongside the raw technical finding message.
- **Arabic**: Generates successfully. Dynamically translates the rule title and description to Arabic based on the shared metadata dictionary, preserving the raw technical finding message as supplementary evidence.

### Excel Verification
- **English**: Generates successfully. WCAG Findings sheets (both Classic and Raawi versions) display the English rule title prominently, appending the WCAG ID on a new line within the same cell. Descriptions are similarly localized.
- **Arabic**: Generates successfully. Translates the rule titles and descriptions to Arabic in the Excel sheet cells based on the requested locale.

### Fallback Behavior
- **Missing WCAG ID**: If a finding does not map to a known WCAG ID in the dictionary (e.g., heuristic/vision rules), the generators gracefully fall back to displaying the raw ID and the raw technical message without crashing.
- **Distinguishing Missing Metadata**: The absence of a localized title naturally degrades to the raw DB values, preventing false claims of localization.
