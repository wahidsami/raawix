## 3. Part B — Verification of Corrections Against Upstream Evidence

### 3.1 Upstream Evidence Analysis
In scan `scan_1792646398336_ukv6vlm`:
- **Layer 1** detected 8 recipe images missing `alt` attributes (`img.Recipe__image`) and 3 low-contrast text elements.
- **Layer 2** detected 8 unsemantic clickable `div`s (`clickable_unlabeled`) wrapping pencil edit icons (`pencil.e81f7a41.png`).
- **Layer 3** detected focus traps, missing focus indicators, and navigation signals.

### 3.2 Root Cause of Empty `labelOverrides` and `imageDescriptions`
Investigation of `apps/scanner/src/assistive/assistive-map-generator.ts` reveals:

1. **`processImages` (`assistive-map-generator.ts:211-270`):**
   ```ts
   if (this.geminiProvider && artifact.screenshotPath) {
     // Calls Gemini to describe image pixels
     const geminiResult = await this.geminiProvider.describeElement(imagePath, 'image', context);
     if (geminiResult.description) {
       map.imageDescriptions[selector] = { alt: geminiResult.description, ... };
     }
   }
   ```
   There is **no local heuristic fallback** for generating image descriptions when `this.geminiProvider` is inactive. Because external AI keys were disabled on the isolated test VPS per operational boundaries ("No autonomous goal execution, bot bypasses, or external-model configuration changes"), `this.geminiProvider` was `undefined`. Consequently, no `imageDescriptions` were created.

2. **`processVisionFindings` (`assistive-map-generator.ts:143-173`):**
   ```ts
   let label: string | null = finding.detectedText || null;
   if (!label && this.geminiProvider && artifact.screenshotPath) {
     // Try Gemini OCR / icon recognition
   }
   if (label) {
     map.labelOverrides[selector] = { label, ... };
   }
   ```
   The local heuristic vision detector identifies bounding boxes for unlabeled interactive controls (`clickable_unlabeled`), but sets `detectedText: null`. Because `this.geminiProvider` was disabled, `label` remained `null`, resulting in zero `labelOverrides`.

3. **`processActions` (`assistive-map-generator.ts:328-357`):**
   Operates entirely on deterministic DOM inspection (`action.tagName`, button inner text, and card context). Because it does not require external AI, it successfully generated all 9 `actionIntents`.

### 3.3 Assessment
The absence of `imageDescriptions` and `labelOverrides` in the live map is **expected under the currently configured local heuristic vision pipeline**. However, it proves that the live AssistiveMap generated on the test VPS cannot perform DOM remediation on its own without external vision AI enabled or without local heuristic label synthesis.

## 4. Part C — Audit of Blind Agent Finding `RA-001-022`

### 4.1 Finding Details
- **Issue Code:** `RA-001-022`
- **Kind:** `authenticated_workspace_navigation_unclear`
- **Issue Title:** *"Authenticated workspace navigation cues are weak, so account context or exit controls may be hard to discover."*
- **Severity:** Medium (`suggestedWcagIds: ['2.4.6', '2.4.3', '3.3.2']`)
- **Evidence Recorded:**
  ```json
  {
    "pageType": "home",
    "mainHeading": "Recipe Dashboard (with intentional a11y issues)",
    "landmarks": ["nav", "banner", "main"],
    "hasAccountArea": true,
    "hasLogout": false,
    "accountControls": 0,
    "logoutControls": 0
  }
  ```

### 4.2 Audit & Defect Root Cause
Inspection of `https://broken-workshop.dequelabs.com/` confirms:
- The site is a **public cooking recipe demonstration**.
- It contains **zero user accounts, zero login forms, zero authentication tokens, and zero session state**.
- `accountControls` was **0**; `logoutControls` was **0**; `pageType` was `'home'`.

Why did the scanner flag it?
In `apps/scanner/src/agent/page-understanding.ts`:
1. **Loose Signal Matching (lines 455-469):**
   `hasAuthenticatedWorkspace` checked `hasWord(['dashboard', 'workspace', 'account', ...])` against the entire page innerText. Because the recipe page had `<h1>Recipe Dashboard</h1>`, the word `"dashboard"` matched, setting `hasAuthenticatedWorkspace: true` and `hasAccountArea: true`.
2. **Unconditional Task Intent Generation (line 284):**
   ```ts
   if (pageType === 'dashboard' || raw.signals.hasAuthenticatedWorkspace) {
     tasks.push({ id: 'navigate-authenticated-workspace', ... });
   }
   ```
   Even though `pageType` was `'home'`, the task intent was attached.
3. **Flawed Diagnostic Rule (lines 809-843):**
   ```ts
   if (!hasWorkspaceStructure || (!profile.signals.hasLogout && profile.counts.logoutControls === 0)) {
     return {
       issue: { kind: 'authenticated_workspace_navigation_unclear', ... }
     };
   }
   ```
   Because a public cooking recipe page does not have a "Log out" button (`logoutControls === 0`), the engine assumed it was an authenticated workspace with missing exit cues and penalized it with `RA-001-022`.

### 4.3 Correction Implemented
In `apps/scanner/src/agent/page-understanding.ts`:
1. **Signal Hardening:** `hasAuthenticatedWorkspace` now requires either actual logout words or workspace keywords accompanied by interactive controls (`accountControls > 0 || logoutControls > 0`) or an authenticated route (`/app/`, `/dashboard/`, `/workspace/`).
2. **Intent Gate:** `navigate-authenticated-workspace` is only attached when `pageType === 'dashboard'` OR when `hasAuthenticatedWorkspace` is backed by concrete interactive account/logout controls.
3. **Evaluation Safety:** If evaluated on a public page with `pageType !== 'dashboard'` and zero account/logout controls, the task returns `result: 'working'` with summary: *"Public content evaluated; no authenticated workspace or account management cues required"*, emitting zero false defects.

### 4.4 Automated Regression Testing
Added `apps/scanner/src/agent/page-understanding.test.ts` (passing):
- Test 1: Verifies that public pages with `"dashboard"` in the heading (matching Deque Broken Workshop) do NOT attach `navigate-authenticated-workspace` and emit zero false findings.
- Test 2: Verifies that real authenticated dashboards (`pageType: 'dashboard'`, `accountControls: 2`, `logoutControls: 0`) continue to detect `authenticated_workspace_navigation_unclear` when exit cues are missing.
- Test 3: Scanner test suite passes 100% (**25 test files, 142 tests passing**).
